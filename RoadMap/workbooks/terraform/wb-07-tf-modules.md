Terraform modules

Модуль — это контейнер для набора ресурсов, которые используются вместе. Каждая Terraform-конфигурация уже является модулем — корневым модулем (root module), который состоит из .tf-файлов в рабочей директории. Модуль, вызываемый другим модулем, называется дочерним модулем (child module).

Без модулей конфигурация становится трудноуправляемой: сложно ориентироваться в файлах, изменения одной части могут сломать другую, появляется дублирование кода (например, для dev/staging/prod), а передача знаний команде затрудняется.

Модули решают это через:

-Организацию — логическое группирование связанных ресурсов
-Инкапсуляцию — сокрытие деталей реализации
-Переиспользование — один раз написал, используешь везде
-Консистентность — единые best practices во всей инфраструктуре
-Self-service — другие команды могут использовать модуль без глубокого знания Terraform

Рекомендуемая структура директорий
Путь	                          Назначение
main.tf	                          Определения ресурсов (execution layer)
variables.tf	                  Входные переменные (contract модуля)
outputs.tf	                      Выходные значения для вызывающего модуля
versions.tf	                      Требования к провайдерам и версии Terraform
README.md	                      Документация модуля
examples/	                      Примеры использования
locals.tf	                      Локальные значения (при необходимости)
data.tf	                          Data sources (если их много)

Модуль вызывается блоком module:
module "servers" {
  source = "./app-cluster"

  servers = 5
}

source — обязательный аргумент для всех модулей. Это либо локальный путь, либо адрес удалённого источника

Источник	            Пример
Локальный путь	        source = "./modules/namespace"
Public Registry	        source = "hashicorp/consul/aws"
Git (тег)	            source = "git::https://example.com/vpc.git?ref=v1.2.0"
Git (SHA)	            source = "git::https://example.com/vpc.git?ref=51d462976d84fdea54b47d80dcabbf680badcdb8"
Shallow clone	        source = "git::https://example.com/vpc.git?depth=1"


Критически важное правило: provider-блоки должны объявляться только в корневом модуле (у потребителя модуля). Дочерние модули не должны конфигурировать провайдеры.

Дочерний модуль должен декларировать требования к провайдерам в versions.tf:
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 4.0"  # только 4.x, не 5.0
    }
  }
}


Best Practices:
-Плоское дерево модулей — избегайте глубокой вложенности
-Один ресурс — имя this — если он один в модуле
-Все переменные с типом — и validation где возможно
-Outputs ссылаются на атрибуты ресурсов, а не на переменные
-Провайдеры только в root-модуле
-Версионируйте модули — через version (registry) или ref (git)
-README.md обязателен для внешних модулей
-examples/ с рабочими примерами
-moved blocks при рефакторинге
-Не создавайте модули-обёртки без реальной абстракции
